# Agent 语义评测评分细则 · manuscript-audit

本细则用于**人工**比较：盲测工作区中的原始 Agent 输出 ↔ 仓库内 `expect.json` / `evals/expected/`。

程序确定性结果（`tools/run_evals.py`）与本细则**分开报告**，不得混算为同一 pass 率。

## 1. 有效盲测前提

一次评分记为**有效盲测**，须同时满足：

1. Agent 会话**未**打开过该案例的 `expect.json`、`evals/expected/`、本 rubric 中针对该案的答案段落，或已填好的 scorecard。
2. 工作区仅含盲测包（`input.md` + `TASK.md` + 可选 Skill 指令），**不含**标准答案。
3. 保存的是**未经人工改写**的原始审计输出（可另存人工修订版，但评分以原始版为准）。
4. 记录了日期、Agent/模型、Skill 源标识（git commit 或安装路径版本说明）。

同一会话中先看过答案再“重跑” → **无效盲测**，可记为练习，不得计入正式汇总。

## 2. 每条预期发现的维度

对 `agent_expectations.must_find[]` 中每一项，独立打分：

| 维度 | 通过 | 失败 |
|------|------|------|
| 检出 | 报告了对应问题（表述可不同，语义对齐即可） | 完全漏检 |
| 漏检 | — | 计入 miss |
| 误报 | 未对 `must_not` / 干净对照捏造错误级问题 | 无问题内容被报为 Critical/已证实错误 |
| 严重程度 | 落在 `severity_band` 内，或合理偏保守（Needs Review） | 明显过重（无据 Critical）或明显过轻且掩盖关键冲突 |
| 证据支撑 | 结论可由输入材料支持 | 无依据事实判断 |
| 证据位置 | 能在原文找到对应句/段 | 位置虚假或不可定位 |
| evidence_state | 落在允许集合；未核实不标 `verified` | 未核实却标 `verified` |
| 候选升级 | 脚本候选未在无额外证据时抬成 Critical | 过度升级 |
| 建议 | 修订建议不要求伪造实验/数据 | 建议与材料矛盾或要求造假 |

## 3. 案例级判定

| 结果 | 条件 |
|------|------|
| `pass` | 全部 `must_find` 检出；无严重 `must_not` 违规；无不合理 Critical/`verified` |
| `fail` | 关键漏检，或严重误报 / 无依据事实判断 / 禁令违规 |
| `partial` | 检出主要问题但严重程度或 loci 明显偏差（记入汇总，**不算** pass） |
| `skip` | 未执行、会话污染、材料缺失、无法判断 | 

**`skip` 与 `partial` 一律不得计入 pass。**

## 4. 汇总指标（人工计算）

在有效案例集合上报告：

- **关键问题召回**：检出的 must_find 数 / must_find 总数  
- **误报**：干净或合法差异案例中的错误级误报次数；以及 `must_not` 违规次数  
- **严重程度合理率**：severity 落在 band 或合理保守的比例  
- **证据定位质量**：有可核验 Location/Evidence 的比例  
- **未执行 / 无法判断**：单独列表

有效测试过少时，**不得**据此宣称 Stable；保持 Draft。

## 5. 与程序测试的边界

| 类型 | 工具 | 计入 |
|------|------|------|
| 确定性脚本 | `python tools/run_evals.py` | 本地 pass/fail/skip |
| Agent 语义 | 本 rubric + scorecard | 仅实际执行并人工评分后 |

语义案例在本地运行器中永远是 skip，这是设计而非失败。
