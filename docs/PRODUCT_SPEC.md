# 产品规格 · ScholarlyOps

品牌与命名以仓库根目录 [`project.json`](../project.json) 为准。

- 品牌名：ScholarlyOps  
- 中文名：学术研究工作流 Skills  
- 英文副标题：Evidence-grounded AI skills for the research lifecycle.  
- 中文副标题：基于科研证据的可扩展 AI 工作流技能集。

## 1. 核心价值

在科研生命周期中，用可安装、可测试的 Agent Skills，把“写得像样”约束为“证据站得住、修改可审计、错误可分级”。

## 2. 目标用户

| 用户 | 典型任务 |
|------|----------|
| 研究生 / 博士后 | 整理材料、起草段落、投稿前自查 |
| 通讯作者 / 导师 | 全文一致性审计、审稿意见分流 |
| 开源维护者 | 扩展 Skill、评测与验证规则 |

## 3. 范围内 / 范围外

**范围内（当前阶段）**

- 研究上下文结构化
- 文献检索策略规划（默认 Strategy Only）
- 证据约束写作
- 论文一致性审计（示范重点）
- 审稿意见回复映射
- 仓库级结构验证与合成评测

**范围外（近期不做或不声称已完成）**

- 自动向期刊投稿
- 保证查重通过或中稿
- 无人复核的科学结论背书
- 虚构数据库命中数 / 题名 / DOI
- 未实测的多 Agent 一键安装器
- 未选型的文献 API 付费集成（可作为 Search Assisted 的未来选项，当前不声称已完成）

## 4. Skill 职责边界

| Skill | 负责 | 不负责 |
|-------|------|--------|
| `research-context` | 结构化记录；区分事实/解释/推论/缺失/待核实 | 编造缺失实验或统计 |
| `literature-search` | 问题框架、关键词矩阵、分库检索式、迭代与检索记录模板 | 编造命中/DOI；编造已核实 MeSH；宣称完整系统综述检索合规 |
| `evidence-writing` | 主张—证据映射下的起草/改写 | 为文采夸大结论或虚构文献 |
| `manuscript-audit` | 分级审计报告；程序可检项优先脚本化 | 擅自改写并覆盖原稿 |
| `review-response` | 意见拆分与修改/证据/状态关联 | 声称未完成实验或修改已完成 |

## 5. 学术完整性（权威摘要）

### 5.1 事实保真

未经授权不得改变：样本量与次数、数值与单位、设计与对照、相关 vs 因果、显著性与置信区间、结论范围、文献原意。可能改变科学含义时：保留原意、标风险、请作者确认。

### 5.2 证据状态

`verified` | `partially_supported` | `unverified` | `unsupported` | `conflicting`

模型“觉得合理”≠ `verified`。缺少证据 ≠ 结论为假；未核实不得直接标为已确认错误。

### 5.3 引用分层

1. 文献是否存在  
2. 元数据是否正确  
3. 内容是否支持主张  
4. 论证使用是否恰当  

### 5.4 修改可审计

记录原文、修订、理由、证据位置、是否改原意、待确认项。默认不覆盖原稿。

## 6. 输入 / 输出 / 异常 / 验收

**输入**：用户文本、图表说明、参考文献列表、审稿意见、任务目标。  
**输出**：结构化 Markdown 报告；证据状态；限制声明；待确认清单。  

**异常**：材料不足 → 列缺失并降级；矛盾 → `conflicting`；不可读附件 → 标无法判断；要求伪造 → 拒绝该部分。

**验收原则**：文档与目录一致；验证工具可运行；成熟度与测试记录一致；不虚构功能。

## 7. 程序检查 vs 语义判断 vs 人工

| 类型 | 示例 | 执行方 |
|------|------|--------|
| 程序 | 同指标两处数值字符串冲突；简单单位 token | 脚本 |
| 语义 | 相关→因果；引文是否支持论点 | 模型（须给位置） |
| 人工 | 是否可发表；伦理与作者意图 | 作者/专家 |

## 8. 依赖关系

```text
research-context ──► literature-search（可选）──► evidence-writing
        │                                            │
        └──────────► manuscript-audit ◄──────────────┘
                           │
                    review-response（可独立）
```

各 Skill 可独立安装。推荐流水线：上下文 →（检索策略）→ 写作 → 审计 → 审稿回复。

## 9. 成熟度

| 级别 | 含义 |
|------|------|
| Draft | 流程清晰；测试不充分 |
| Beta | 主路径已测；限制已公开 |
| Stable | 公开评测、关键错误门槛与真实任务验证均有记录 |

当前五 Skill 均为 **Draft**。

## 10. 已完成 vs 未实现

**已完成（骨架与示范级）**：中英文文档、五 Skill Draft（含 `literature-search`）、`manuscript-audit` 合成评测与检查脚本、`literature-search` 合成案例（语义待人工）、仓库验证器与 CI 工作流入口。

**未实现**：正式许可证与公开发布、Beta/Stable 升级、真实稿件验证记录、付费文献 API 集成、`literature-search` 有效盲测与大规模真实库执行记录、绘图/统计扩展 Skill。
